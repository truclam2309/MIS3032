# US-03 — Xem và xử lý Approval

- **Story/AC nguồn:** [US-03 gốc](../../03-product/user-stories.md), AC1–AC4.
- **Requirements:** REQ-FR-05–07; REQ-BR-02–04; REQ-NFR-02–03.
- **Vai trò quyết định:** Chỉ Manager. Admin không có quyền Approval theo phạm vi đã xác nhận.
- **API:** `GET /purchase-requests`; `POST /purchase-requests/{request_id}/decision`.
- **Action hợp lệ:** `approved`, `rejected`, `revision`.
- **Điều kiện xử lý:** PR phải ở `PENDING_APPROVAL`; quyết định lặp trả `400`; PR không tồn tại trả `404`; role khác Manager trả `403`.
- **Trạng thái sau quyết định:** Approve → `APPROVED` và `next_approval_role=Finance`; Reject → `REJECTED`; Revision → `REVISION_REQUIRED`.
- **Lưu trữ:** Memory khi `USE_SUPABASE=false`; bảng `purchase_requests` khi bật Supabase. Workflow response được tính từ trạng thái, không lưu thành cột.
- **Kiểm thử:** [5 test memory](../../../../backend-test/test_approval.py), [5 test Supabase](../../../../backend-test/test_approval_supabase.py).
- **Kết quả:** 5/5 pass ở mỗi chế độ vào ngày 2026-09-26.

## Đánh giá Acceptance Criteria

| AC | Hiện trạng |
|---|---|
| AC1 — Manager mở PR và xem thông tin | API đọc PR có; chưa kiểm tra UI hoặc object-level scope. |
| AC2 — Manager Approve và tiếp tục workflow | Approve chuyển trạng thái và chỉ ra Finance là bước kế tiếp; chưa có Finance decision endpoint. |
| AC3 — Reject hoặc Request Revision | Đã có ở backend; hai action được test trên memory và Supabase. |
| AC4 — Chuyển theo workflow cấu hình | Chưa hoàn tất; hierarchy hiện cố định và Finance chưa thể xử lý tiếp. |

## Phần còn thiếu

- Finance handoff/decision và test của bước Finance.
- Resubmission sau khi PR bị yêu cầu chỉnh sửa.
- Audit trail dạng sự kiện nối tiếp; hiện chỉ có metadata quyết định gần nhất.
- UI/E2E test để xác minh quyền và điều hướng frontend.
